# TSOA + Koa Todo List REST API (Hexagonal Architecture)

A full-fledged, production-ready backend project demonstrating how to build a RESTful API using **Koa** framework and **TSOA** (TypeScript OpenAPI generator) using **Hexagonal Architecture** (Ports and Adapters pattern).

---

## 🏗️ Architecture Overview

The project strictly follows **Hexagonal Architecture** (Ports & Adapters) to ensure complete separation of concerns and decoupling of business logic from infrastructure/frameworks:

```
src/
├── domain/                          # 🧠 Core Domain (Entities, Value Objects, Domain Exceptions)
│   ├── models/
│   │   └── todo.model.ts            # Entities, Enums (Status, Priority) & DTOs
│   └── exceptions/
│       └── todo.exception.ts        # Domain-specific Exceptions
│
├── ports/                           # 🔌 Ports (Interfaces for Inbound & Outbound communication)
│   ├── inbound/
│   │   └── todo.service.port.ts     # Primary Port (Use Cases exposed by Application layer)
│   └── outbound/
│       └── todo.repository.port.ts  # Secondary Port (Persistence Interface contract)
│
├── application/                     # ⚙️ Application / Business Services
│   └── services/
│       └── todo.service.ts          # Core Use Case implementations (validations, rules)
│
├── infrastructure/                  # 🛠️ Infrastructure (Adapters & Framework integration)
│   ├── adapters/
│   │   ├── persistence/
│   │   │   └── in-memory-todo.repository.ts  # Outbound Adapter (Mock In-Memory Repository)
│   │   └── http/
│   │       ├── controllers/
│   │       │   └── todo.controller.ts        # Inbound Adapter (TSOA Koa Controller)
│   │       └── middleware/
│   │           └── error-handler.middleware.ts # Koa Error Mapper
│   ├── config/
│   │   └── env.config.ts            # Environment configurations
│   └── container.ts                 # Composition Root / Dependency Injection Container
│
├── generated/                       # 🤖 Auto-generated by TSOA
│   ├── routes.ts                    # Koa Router bindings generated by TSOA
│   └── swagger.json                 # OpenAPI 3.0 specification file
│
└── server.ts                        # 🚀 Koa Server bootstrap & Swagger UI mount
```

## 🚀 Quick Start

### 1. Install Dependencies
```bash
npm install
```

### 2. Run in Development Mode
Runs TSOA watcher for auto route generation alongside auto-reloading server:
```bash
npm run dev
```

### 3. Build & Run for Production
```bash
npm run build
npm start
```

## 📚 API Documentation & Endpoints

Once the server is running on `http://localhost:3000`:
- **Interactive Swagger UI**: [http://localhost:3000/docs](http://localhost:3000/docs)
- **OpenAPI JSON Spec**: [http://localhost:3000/swagger.json](http://localhost:3000/swagger.json)
- **Health Check**: [http://localhost:3000/health](http://localhost:3000/health)

### Available REST Endpoints

| Method | Endpoint | Description | Query / Body Params |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/todos` | List all todos | `status`, `priority`, `search`, `tag` |
| `GET` | `/api/todos/stats` | Summary statistics | None |
| `GET` | `/api/todos/:id` | Get todo by ID | Path `:id` |
| `POST` | `/api/todos` | Create new todo | Body: `CreateTodoRequest` |
| `PUT` | `/api/todos/:id` | Update todo | Path `:id`, Body: `UpdateTodoRequest` |
| `PATCH` | `/api/todos/:id/status` | Change todo status | Path `:id`, Body: `{ "status": "COMPLETED" }` |
| `DELETE` | `/api/todos/:id` | Delete todo by ID | Path `:id` |

## 🧪 Example Requests (cURL)

### 1. Create a New Todo
```bash
curl -X POST http://localhost:3000/api/todos \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Build Frontend Application",
    "description": "Connect React or Vue frontend with Koa & TSOA backend",
    "priority": "HIGH",
    "tags": ["frontend", "react"],
    "dueDate": "2026-10-15T00:00:00.000Z"
  }'
```

### 2. Get All Todos (Filtered by Status)
```bash
curl "http://localhost:3000/api/todos?status=IN_PROGRESS"
```

### 3. Get Todo Statistics
```bash
curl http://localhost:3000/api/todos/stats
```

### 4. Update Todo Status
```bash
curl -X PATCH http://localhost:3000/api/todos/todo_seed_002/status \
  -H "Content-Type: application/json" \
  -d '{ "status": "COMPLETED" }'
```

## 💡 How TSOA Works with Koa

1. **TSOA Annotations**: In [`src/infrastructure/adapters/http/controllers/todo.controller.ts`](file:///d:/Projects/tsoa/src/infrastructure/adapters/http/controllers/todo.controller.ts), controllers are decorated with `@Route`, `@Get`, `@Post`, `@Body`, `@Query`, `@Path`, `@Response`, `@SuccessResponse`.
2. **Route Generation**: Running `npx tsoa spec-and-routes` reads `tsoa.json`, scans controller files, generates [`src/generated/routes.ts`](file:///d:/Projects/tsoa/src/generated/routes.ts) tailored for `@koa/router`, and creates [`src/generated/swagger.json`](file:///d:/Projects/tsoa/src/generated/swagger.json).
3. **Koa Router Mounting**: In [`src/server.ts`](file:///d:/Projects/tsoa/src/server.ts), `RegisterRoutes(router)` automatically registers all controller endpoints to Koa router instance with parameter parsing and response handling.
